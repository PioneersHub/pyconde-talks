{% if schedule_items %} {% comment %} Two renderings of the same day. A grid of rooms cannot be read on a 360px screen: it was five columns wide and needed sideways scrolling to see any of them, and this page is the one attendees open most from a phone. Below md the day is a single column of time slots instead, which is the same information in the order you actually consume it. Which one shows is down to the stylesheet, keyed on data-view here: empty means the viewport decides, "grid" means the grid at every width. See the .schedule-layout rules in input.css. Every talk therefore appears twice in the markup, and only one copy is ever displayed. The bookmark buttons need distinct wrapper ids for that reason, hence variant="agenda-". {% endcomment %} {% comment %} The switch is for phones: from md up the grid is already what shows, so there is nothing to override and the control would only be one more thing in the way. Landing on ?view=grid on a desktop therefore changes nothing, which is why the parameter is allowed to survive in shared links and in the day and filter navigation below. {% endcomment %}
